# 《엄마에게》 — 설계 문서

- 날짜: 2026-11-09
- 주제: 새끼 바다표범이 점프와 꼬리치기로 위험을 넘어 엄마에게 도착하는 횡스크롤 게임
- 엔진: Godot 4.7.2 (GDScript)
- 상태: 승인 대기

---

## 1. 의도와 이유

아기 물범이 빙하를 가로질러 엄마 물범에게 도착하는 2D 횡스크롤 플랫포머.

핵심은 **두 개의 동사**입니다. 점프와 꼬리치기. 둘 다 없으면 어떤 레벨도 클리어할 수 없어야 하고, 둘 다 있어야만 깔끔하게 클리어되는 구조를 목표로 합니다.

레벨마다 난이도가 오르지만, **"오른쪽 끝의 엄마에게 도착한다"는 목표는 모든 레벨에서 동일**합니다. 레벨이 바뀌면 길이·밀도·새로운 위험이 늘어날 뿐, 플레이어가 해야 할 일의 성격은 변하지 않습니다. 그래서 실력이 쌓이는 느낌이 목표가 아니라, 같은 목표를 더 빡빡한 조건에서 반복하는 데서 옵니다.

두 번째 맥락: 그림은 사용자가 Midjourney로 직접 제작합니다. 지금은 그림 파일이 하나도 없습니다. 따라서 **도형으로 만든 퍼펫을 먼저 완성하고, 그림이 도착하면 파츠만 교체**하는 구조가 필수입니다. 이 요구사항이 아키텍처를 결정합니다.

---

## 2. 목표 / 비목표 / 안티목표

### 목표

- 5개 레벨을 순서대로 클리어할 수 있다.
- 점프와 꼬리치기가 **둘 다 필수**다. 꼬리치기를 안 쓰면 클리어 불가능한 구간이 레벨 2부터 존재한다.
- 그림 파일 없이도 완결된 게임으로 플레이 가능하다.
- PNG가 도착하면 코드를 건드리지 않고 파츠를 교체할 수 있다.
- `godot --headless` 로 씬 로드와 기본 시뮬레이션을 검증할 수 있다.

### 비목표

- 멀티플레이, 온라인, 리더보드
- 모바일 터치 조작 (키보드 전용. 터치는 별도 요청 시)
- 스토리 컷신, 대화, 인벤토리
- 레벨 에디터
- 업적, 세이브 슬롯 여러 개

### 안티목표

기술적으로 동작하는데도 실패로 보는 것:

- **꼬리치기가 장식이 되는 것.** 점프만으로 전 레벨을 깰 수 있으면 설계 실패입니다.
- **레벨마다 목표가 달라지는 것.** "물고기 10마리 모으기", "제한 시간 안에 도착" 같은 부목표가 생겨서 목표가 분산되면 실패입니다. 시간 압박은 레벨 5의 환경 조건이지 목표가 아닙니다.
- **입력 씹힘.** 점프를 눌렀는데 반응이 없으면 안 됩니다. 코요테 타임과 점프 버퍼로 막습니다.
- **프레임 드랍.** 640×360 뷰포트에서 60fps를 유지합니다.
- **그림 없이는 플레이 불가능한 상태.** 도형 아트만으로 완결되어야 합니다.

### 3.1 해상도를 640×360으로 하는 이유

물범의 시각적 크기가 약 72px로 충분히 읽히면서, 화면에 들어가는 레벨 구간이 짧아 점프 난이도를 눈으로 판단하기 쉽습니다. 1920×1080에서 300px짜리 물범은 점프 거리 감각이 무뎌집니다. 또한 저해상도는 도형 아트의 거친 가장자리를 의도된 스타일처럼 보이게 합니다.

## 4. 접근법

### A. 스프라이트 시트 중심

`AnimatedSprite2D` + 스프라이트 프레임으로 모든 것을 해결. 그림이 있으면 가장 좋습니다.
**기각 이유:** 그림 파일이 하나도 없습니다. 첫 플레이 가능 버전까지 막혀 있습니다.

### B. 완전 도형 퍼펫

파츠를 `Polygon2D`로 그리고 코드가 위치·스케일·회전을 직접 조작.
**채택하지 않는 이유:** 지금은 잘 동작하지만, 나중에 PNG로 갈아끼우려면 퍼펫 제어 코드와 충돌합니다. 코드가 `BodyPivot.scale`을 매 프레임 쓰고 있는데 스프라이트가 들어오면 누가 누구를 이기는지 애매해집스.

### C. 하이브리드 — 피벗 퍼펫 + 시각 슬롯 (채택)

**채택.** 구조는 이렇습니다:

- 파츠마다 **피벗 노드** (`Node2D`) 를 둡니다. 피벗은 위치만 가지고, 시각을 직접 갖지 않습니다.
- 피벗 아래에 **시각 슬롯** (`Node2D`) 을 두고, 현재는 `PolygonPuppet`(도형)을, 미래에는 `AnimatedSprite2D`(PNG)를 붙입니다.
- **애니메이션은 `AnimationPlayer`가 피벗 노드를 직접 조작**합니다. 시각 노드는 건드리지 않습니다.

이 구조의 핵심 이점: `AnimationPlayer`의 트랙 타겟이 `BodyPivot:scale`, `HeadPivot:rotation` 같은 **피벗의 프로퍼티**이므로, 시각 자식을 교체해도 애니메이션은 그대로 동작합니다. 스프라이트로 바꾸면 피벗은 rest pose로 남아 있고 스프라이트 프레임이 시각을 담당합니다. 서로 싸우지 않습니다.

이것이 B와의 결정적 차이입니다. B는 코드가 매 프레임 파츠를 쓰작거려서 교체 시 충돌하고, C는 애니메이션이 피벗만 보므로 교체가 자유롭습니다.

파츠의 파일명·원점 규격은 이미 `png-prompts.md` 에 확정해 두었습니다. 이 설계는 그 규격에 정확히 일치하도록 되어 있습니다.

## 5. 코어 루프

### 5.1 이동

| 항목 | 값 |
|---|---|
| 중력 | 900 px/s² |
| 점프 초속 | −320 px/s (약 57px 상승) |
| 가변 점프 | 점프키를 떼면 상승 속도를 45%로 즉시 감속 |
| 최대 이동 속도 | 130 px/s |
| 가속도 | 900 px/s² |
| 지면 마찰 감속 | 600 px/s² |
| 공중 가속도 | 지면의 60% |
| 코요테 타임 | 0.10초 |
| 점프 버퍼 | 0.12초 |
| 더블 점프 | 없음 |

빙판 위라서 관성 기반으로 미끄러지는 느낌을 줍니다. 가속과 마찰이 분리되어 있어서 "눌렀을 때 서서히 붙고, 뗐을 때 미끄러지다 멈추는" 감각이 납니다.

코요테 타임과 점프 버퍼는 입력 씹힘을 막기 위한 것입니다. 낭떨어지 가장자리에서 점프를 눌렀는데 아직 공중인 경우, 착지 후 0.12초 안에는 눌림이 기억됩니다. 반대로 지면을 막 떨어진 직후 0.10초 안에는 점프가 허용됩니다.

### 5.2 꼬리치기

| 항목 | 값 |
|---|---|
| 입력 | `J` / `Z` |
| 활성 시간 | 0.15초 |
| 쿨다운 | 0.40초 |
| 범위 | 정면 부채, 반경 44px, 수직 32px |
| 공중 사용 | 가능. 공중에서 쓰면 시전자를 앞으로 40px/s 밀음 |
| 지면 사용 | 사용 순간 마찰을 0.15초간 3배로 (제자리에 딱 멈추는 느낌) |
| 넉백 | 맞은 적을 220px/s로 밀어냄 |
| 반동 | 적이나 블록을 맞히면 시전자를 위로 150px/s 띄움 |

꼬리치기의 세 가지 효과가 각각 레벨 디자인에서 쓰입니다:

1. **적 제거** — 갈매기와 게를 넉백시켜 파괴합니다.
2. **반동 점프** — 위로 150px/s 띄워주므로, 일반 점프로는 못 닿는 높이에 도달할 수 있습니다. 이게 꼬리치기를 **이동 수단**으로 만드는 부분입니다.
3. **제동** — 빙판에서 미끄러지는 중에 쓰면 멈춥니다. 좁은 발판에서 방향을 잡는 용도.

게는 **밟으면 죽고 꼬리치기로만 죽습니다.** 이 규칙이 꼬리치기를 강제하는 핵심 장치입니다. 갈매기는 점프로 회피도 가능하지만, 좁은 구간에서는 꼬리치기가 더 안전합니다.

### 5.3 위험 요소 (혼합형)

**환경 / 지형**

| 요소 | 동작 |
|---|---|
| 얇은 얼음 | 밟으면 0.3초 후 깨지고 추락. 금 간 표면으로 위험을 예고 |
| 고드름 | 매달려 있다가 플레이어가 아래로 지나가면 낙하 |
| 물 (빙하 틈) | 닿으면 즉사 |
| 깨지는 얼음 블록 | 꼬리치기로 파괴. 길을 막는 장애물이자 발판 |

**생물**

| 요소 | 동작 | 대응 |
|---|---|---|
| 갈매기 | 좌우 직선 비행, 플레이어를 추격하지 않음 | 점프 회피 또는 꼬리치기 제거 |
| 게 | 바닥 좌우 순찰 | **밟으면 사망. 꼬리치기로만 제거** |

생물은 의도적으로 단순하게 합니다. 갈매기는 직선 비행만, 게는 좌우 순찰만. 추적 AI는 넣지 않습니다. 예측 가능한 패턴이어야 플레이어가 "점프로 갈까, 꼬리로 칠까"를 판단하는 재미가 생깁니다.

### 5.4 목표

각 레벨 오른쪽 끝에 엄마 물범이 빙하 위에 서 있습니다. 도달하면 레벨 클리어. **모든 레벨에서 동일합니다.**

### 5.5 실패와 재시도

| 항목 | 값 |
|---|---|
| 체력 | 하트 3개 |
| 피격 | 넉백 + 무적 1.2초 + 하트 1 감소 |
| 사망 | 하트 0 또는 물/추락에 닿음 |
| 부활 | **마지막으로 통과한 체크포인트.** "즉시"는 로딩 화면이 없다는 뜻이며, 사망 지점에서 되살아난다는 뜻이 아니다 |
| 체크포인트 | 레벨마다 1~2개 (난이도에 따라 감소) |

사망 시 씬을 리로드하지 않고 플레이어 위치·체력·파괴된 오브젝트만 리셋합니다. 리로드하면 적이 전부 되살아나서 클리어 불가능해지는 구간이 생길 수 있기 때문입니다.

부활 지점을 사망 지점으로 하면 체크포인트가 순전히 장식이 되고, 구멍이나 물에 빠져 죽은 경우 되살아날 지면이 없어 막힙니다. 따라서 부활은 항상 체크포인트입니다. 이 결정이 곧 체크포인트가 기능적인 구조인지 장식인지를 정합니다.

**"통과"의 판정 규칙 (태스크 14에서 확정):** 물범의 x >= 체크포인트의 x 이면 통과한 것으로 본다. 체크포인트는 지면 표면(y=0)에 세워지므로 y는 비교하지 않는다 — 공중을 지나가는 것도 지나간 것으로 본다. 부활 지점은 뒤로 물러나지 않는다(가장 멀리 간 체크포인트만 남긴다). 그렇지 않으면 구멍에 빠져 죽었을 때 이미 통과한 체크포인트 대신 그 앞의 지점에서 살아나, 다시 같은 구멍에 빠지는 무한 루프가 된다. 부활은 `BabySeal.respawn_at()`을 타고, 그 `respawned` 시그널로 빙산 재배치(5.7)와 HUD 물고기 카운터 재시드가 일어난다.

### 5.6 수집

물고기를 길에 배치합니다. 클리어에 필수는 아니고, 클리어 화면에서 "물고기 N / M" 으로만 표시됩니다. 안티목표에서 부목표를 금지했으므로, 클리어 조건에는 절대 넣지 않습니다.

### 5.7 밀려오는 빙산 (레벨 5)

| 항목 | 값 |
|---|---|
| 이동 속도 | 40 px/s, 좌→우 |
| 판정 | **소프트 월.** 즉사하지 않음 |
| 접촉 효과 | 하트 1 감소 + 플레이어를 왼쪽으로 180px/s 넉백 |
| 재접촉 | 무적 1.2초 종료 후 다시 적용 |
| 부활 시 처리 | 부활 지점 x − 400 으로 재배치. 절대 플레이어를 덮치지 않음 |

즉사로 만들면 한 번의 실수가 레벨 전체를 잃게 되어 "압박"이 아니라 "벽"이 됩니다. 소프트 월로 하면 빙산이 플레이어를 재촉하지만, 실수해도 하트 1개로 끝나고 다시 전진할 수 있습니다.

부활 시 재배치 규칙이 필요한 이유는, 그렇지 않으면 체크포인트에서 되살아난 직후 빙산이 플레이어를 덮쳐서 다시 죽는 무한 루프에 빠지기 때문입니다.

### 5.8 꼬리치기를 필수로 만드는 두 장치 (A+B)

꼬리치기가 장식이 되지 않으려면, 점프만으로는 물리적으로 통과할 수 없는 구간이 레벨 2부터 존재해야 합니다. 두 장치를 쓰고, 각각 다른 레벨에서 도입합니다.

**장치 A — 얼음 벽 (레벨 2)**

점프 상승 높이(약 57px)로는 넘을 수 없는 높이의 깨지는 얼음 블록을 길에 세웁니다. 꼬리치기로 부숴야만 지나갈 수 있습니다.

- 블록 높이: 90~110px (점프 불가, 꼬리치기 필수)
- 배치: 레벨 2의 앞 1/3. 첫 블록은 1개만, 주변 지면을 넓게 해서 실패해도 죽지 않게 합니다.
- 시각적 예고: 금 간 얼음이라 "부술 수 있다"는 암시가 있어야 합니다. 매끈한 벽처럼 보이면 플레이어가 방법을 모릅니다.

**장치 B — 반동 점프 (레벨 3)**

꼬리치기가 적이나 블록에 맞으면 시전자를 위로 150px/s 띄웁니다(5.2). 이 반동을 쓰면 점프 한 번으로 못 닿는 높은 발판이나 먼 틈에 도달합니다. 꼬리치기가 **공격 도구에서 이동 수단**으로 바뀌는 지점입니다.

- 배치: 레벨 3부터. 반동 없이는 건널 수 없는 틈과, 반동으로만 닿는 높은 발판.
- 반동 대상: 발판 주변에 게나 작은 얼음 블록을 함께 놓아 "칠 것"이 항상 보이게 합니다. 대상이 없으면 반동을 쓸 수 없어 막힙니다.

**두 장치가 만족해야 할 산술 조건**

| 조건 | 값 |
|---|---|
| 평면 점프 최대 도달 거리 | 92px (0.71초 × 130px/s) |
| 반동 1회 추가 거리 | 실측 142.3px (설계 산술 +43px → 135px는 보수적이었음) |
| 레벨 5 최대 틈 | 170px |

레벨 5의 170px는 반동 1회(실측 142.3px)로도 부족하므로, **높은 곳에서 뛰어내리거나(약 150px 고저차)** 해결해야 합니다. 단, 실측 결과 **반동 2회가 도달거리를 늘리지 않는다**(142.3px = 142.3px). 따라서 생성기는 틈 너비를 단일 반동 도달거리 이내로 clamp하며, 난이도 표의 `recoil_max_gap_px`(130/150/170)는 의도한 최대로 남고 실제 생성만 성립시킨다.

**레벨 1에는 두 장치가 전혀 없습니다.** 점프만으로 클리어합니다. 레벨 2에서 A가, 레벨 3에서 B가 등장하고, 그때부터 꼬리치기가 필수가 됩니다. 이 순서가 "안 쓰면 클리어 불가능"을 참으로 만들면서도 갑작스럽지 않게 합니다.

## 6. 난이도 상승 규칙

난이도는 **5개 축**으로 상승합니다. 축을 늘리는 대신 값을 키웁니다.

1. **길이** — 레벨이 길어집니다.
2. **밀도** — 1000px당 위험 요소 개수가 늘어납니다.
3. **새 메커닉** — 레벨마다 정확히 하나의 새 메커닉이 등장합니다.
4. **점프 난이도** — 반동이 필요한 최대 틈 폭이 늘어납니다.
5. **시간 압박** — 마지막 레벨에서만 뒤에서 밀려오는 빙산이 추가됩니다.

동시에 **체크포인트는 줄어듭니다.** 후반으로 갈수록 같은 실수에 더 관대하지 않습니다.

| 파라미터 | L1 | L2 | L3 | L4 | L5 |
|---|---|---|---|---|---|
| 길이 (px) | 2400 | 3000 | 3600 | 4200 | 4800 |
| 새 메커닉 | (없음 — 점프만) | 꼬리치기 (얼음 벽) | 반동 점프 | 갈매기 | 고드름 |
| 꼬리치기 강제 수단 | 없음 | 얼음 벽 | 벽 + 반동 틈 | 벽 + 반동 틈 | 벽 + 반동 틈 |
| 평면 최대 틈 (px) | 90 | 90 | 92 | 92 | 92 |
| 반동 필요 최대 틈 (px) | — | — | 130 | 150 | 170 |
| 적 밀도 (개/1000px) | 2 | 4 | 6 | 8 | 10 |
| 위험 지형 수 | 1 | 3 | 5 | 8 | 11 |
| 체크포인트 | 2 | 2 | 2 | 1 | 1 |
| 시간 압박 | 없음 | 없음 | 없음 | 없음 | 밀려오는 빙산 |
| 적 구성 | 게만 | 게 | 게 + 갈매기 | 게 + 갈매기 | 게 + 갈매기 |

**틈 폭을 두 줄로 나눈 이유.** "평면 최대 틈"은 점프만으로 건나는 틈이라 반드시 92px 이하여야 합니다. "반동 필요 최대 틈"은 꼬리치기 반동이나 고저차가 필요한 틈입니다. L4의 150px와 L5의 170px는 반동 1회(실측 142.3px)로도 부족하므로, 고저차를 쓰거나 생성기가 단일 반동 도달거리 이내로 clamp합니다(8.3).

### 6.1 설계 원칙

**한 레벨에 새 *메커닉*은 정확히 하나.** 레벨 2에서 꼬리치기를 배울 때 갈매기가 같이 등장하면 플레이어가 무엇 때문에 죽었는지 구분하지 못합니다.

메커닉과 표현을 구분합니다. **물은 새 메커닉이 아닙니다.** 레벨 1부터 모든 구멍에 빠지면 죽으므로, 물은 "떨어져 죽는다"는 기존 메커닉의 시각적 표현입니다. 따라서 레벨 4에서 고드름과 물이 같이 나와도 새 메커닉은 고드름 하나뿐이고 원칙이 깨지지 않습니다. `allows_water` 플래그는 구멍을 물로 렌더링할지 비워둘지를 고르는 스위치일 뿐, 새로운 규칙을 추가하지 않습니다.

**새 메커닉은 레벨의 앞 1/3 구간에서 안전하게 등장합니다.** 레벨 2의 처음 800px에는 게 한 마리만 있고 주변에 발판이 넓찍합니다. 꼬리치기를 실패해도 죽지 않는 연습 공간입니다.

**레벨 1에는 꼬리치기가 없습니다.** 점프만으로 클리어합니다. 레벨 2에서 얼음 벽이, 레벨 3에서 반동 틈이 등장하고, 그때부터 꼬리치기가 필수가 됩니다. 이렇게 해야 "안 쓰면 클리어 불가능"이 참이면서도 갑작스럽지 않습니다.

**레벨 5의 새 메커닉은 고드름 하나뿐입니다.** 나머지는 전부 익힌 것의 조합입니다. 마지막 레벨은 배우는 것이 아니라 버티는 구간이고, 시간 압박이 그 역할을 합니다.

## 7. 파츠 조립 구조

### 7.1 아기 물범 씬 트리

```
seal_baby.tscn
└── BabySeal (CharacterBody2D)                     scripts/seal_baby.gd
    ├── BodyPivot (Node2D)
    │   └── VisualSlot (Node2D)
    │       ├── PolygonPuppet (Node2D)             ← 현재: 도형 파츠
    │       │   ├── Body (Polygon2D)
    │       │   └── Belly (Polygon2D)
    │       └── SpriteSwap (Node2D)                ← 미래: AnimatedSprite2D
    ├── HeadPivot (Node2D)  @ (0, -18)
    │   └── VisualSlot (Node2D)
    │       ├── PolygonPuppet (Node2D)
    │       │   ├── Head (Polygon2D)
    │       │   ├── Face (Polygon2D)   ← Head 와 동일 원점
    │       │   └── Whiskers (Polygon2D)
    │       └── SpriteSwap (Node2D)
    ├── TailPivot (Node2D) @ (-20, 4)
    │   └── VisualSlot / PolygonPuppet / SpriteSwap
    ├── FlipperFrontPivot (Node2D) @ (6, 2)
    │   └── VisualSlot / PolygonPuppet / SpriteSwap
    ├── FlipperBackPivot (Node2D) @ (4, 2)
    │   └── VisualSlot / PolygonPuppet / SpriteSwap
    ├── SwatHitbox (Area2D)  — 활성/비활성으로 판정 제어
    ├── Hurtbox (Area2D)
    └── SealAnim (AnimationPlayer)
```

### 7.2 왜 이 구조인가

**피벗은 위치만, 시각은 슬롯에.** 피벗 노드는 씬에서 좌표만 가지고 있습니다. 시각은 `VisualSlot` 아래에 붙습니다. 그림을 교체할 때 `PolygonPuppet`을 지우고 `SpriteSwap` 아래에 `AnimatedSprite2D`를 넣으면 끝입니다. 스크립트는 `VisualSlot`의 자식을 전혀 알지 못합니다.

**`AnimationPlayer`는 피벗만 조작.** 트랙 타겟이 `BodyPivot:scale`, `HeadPivot:rotation`, `TailPivot:rotation`, `FlipperFrontPivot:rotation` 같은 피벗 프로퍼티입니다. 시각 노드를 건드리지 않으므로:

- 도형일 때: 피벗이 움직이면 도형이 함께 움직입니다.
- 스프라이트일 때: 피벗은 rest pose로 남고 스프라이트 프레임이 시각을 담당합니다.

둘이 충돌하지 않습니다. 이것이 접근법 B(코드가 매 프레임 파츠를 직접 조작)를 기각한 이유입니다.

**Face와 Whiskers는 Head와 동일 원점.** `png-prompts.md`의 원점 규칙 C대로 셋 다 목 연결점을 정중앙에 두므로, 씬에서 같은 좌표에 쌓으면 얼굴이 머리에 정확히 붙습니다. 오프셋 보정이 0입니다.

### 7.3 애니메이션 목록

| 이름 | 대상 피벗 | 내용 |
|---|---|---|
| `idle` | Body, Head, Tail | 호흡 스케일 1.0↔1.04, 고개 미세 상하 |
| `run` | Body, FlipperFront, FlipperBack, Tail | 스케일 스쿼시, 지느러미 교대 회전 ±35° |
| `jump` | Body, Tail, FlipperFront | 스트레치 0.85×1.15, 꼬리 위로 |
| `fall` | Body, Tail, FlipperFront | 스트레치 1.1×0.92, 꼬리 아래로 |
| `swat` | Tail, FlipperBack | 꼬리 -100°→+70° 왕복, 몸통 반동 |
| `hurt` | Body, Head | 깜빝임 + 넉백 자세 |

애니메이션 길이는 전부 0.3~0.5초 루프 또는 원샷입니다. `hurt`와 `swat`은 원샷이고 나머지는 루프.

### 7.4 엄마 물범 씬 트리

```

└── MomSeal (Node2D)
    ├── BodyPivot / VisualSlot
```

엄마는 `CharacterBody2D`가 아닌 `Node2D`입니다. 가만히 서서 지느러미만 흔들므로 물리가 필요 없습니다.

## 8. 레벨 데이터 구조

레벨을 손으로 노드를 배치하지 않고 **데이터로 기술**합니다. "레벨이 높아감에 따라 난이도가 상승한다"는 요구사항을 파라미터 테이블로 직접 표현하기 위해서입니다. 레벨을 추가하는 것은 행을 하나 더하는 일이 됩니다.

```gdscript
# scripts/level_data.gd
class_name LevelData
extends Resource

@export var level_index: int
@export var length_px: float
@export var flat_max_gap_px: float         # 점프만으로 건너는 틈. 반드시 92 이하
@export var recoil_max_gap_px: float       # 반동/고저차가 필요한 최대 틈. 0 = 없음
@export var enemy_density: float           # 1000px 당 개수
@export var hazard_count: int
@export var checkpoint_count: int
@export var enemy_mix: Array[String]       # ["crab"] → ["crab","crab","seagull"]
@export var allows_thin_ice: bool
@export var allows_icicle: bool
@export var allows_water: bool
@export var has_time_pressure: bool
@export var swat_wall_count: int           # 장치 A: 꼬리치기로 부숴야 하는 얼음 벽 수
@export var recoil_gap_count: int          # 장치 B: 반동 없이는 못 건너는 틈 수
@export var seed_value: int                # 고정 시드 → 재현 가능
```

레벨 1~5는 이 리소스 5개이며, 6장의 표와 정확히 같은 값을 가집니다.

`swat_wall_count`와 `recoil_gap_count`가 꼬리치기를 강제하는 두 장치를 직접 제어합니다. 레벨 1은 둘 다 0이고, 레벨 2는 `swat_wall_count`가 1 이상입니다. **레벨 2부터 이 두 값의 합이 1 이상**이어야 하며, 이것이 2장의 안티목표("꼬리치기가 장식이면 실패")를 데이터 수준에서 보장하는 방법입니다.

### 8.1 생성 방식

`level_generator.gd` 가 `LevelData` 를 받아 지형·적·위험을 배치합니다. 시드는 고정이므로 **같은 레벨은 항상 같은 모양**으로 생성됩니다. 랜덤이 아닙니다.

생성 규칙:

- 지형은 **지면 세그먼트 + 떠 있는 발판**으로 구성됩니다. 평면 복도가 아닙니다.
- 지면은 세그먼트로 나눕니다. 세그먼트 사이의 평면 틈은 `flat_max_gap_px` 이하.
- 첫 세그먼트는 넓고 안전합니다 (600px). 새 메커닉 연습 공간.
- 마지막 세그먼트는 400px이고 끝에 엄마 빙하가 놓입니다.
- 적은 `enemy_density`에 따라 간격을 계산해 배치합니다. 단, 새 메커닉 등장 구간(앞 1/3)에는 밀도의 30%만 배치합니다.
- 체크포인트는 `checkpoint_count`에 따라 균등 배치합니다.
- **얼음 벽(장치 A)**은 `swat_wall_count` 개수를, 레벨의 앞 1/3에 배치합니다. 첫 벽은 지면이 넓은 곳에 하나만. 이후 벽은 간격을 두고 배치합니다.
- **반동 틈(장치 B)**은 `recoil_gap_count` 개수를, 레벨의 뒤 2/3에 배치합니다. 각 반동 틈에는 반동 대상(게 또는 작은 얼음 블록)을 틈 바로 앞에 함께 놓습니다. 대상 없이 반동을 요구하면 막힙니다.

### 8.2 시드 기반을 선택한 이유

레벨을 손으로 배치하면 "난이도가 상승한다"는 것을 보장하려면 5개를 각각 검증해야 합니다. 데이터 + 시드 생성이면 6장의 표가 그대로 난이도 곡선이고, 표를 수정하면 레벨이 즉시 따라옵니다. 손 조정이 필요해지면 그때 생성 결과를 씬으로 굽는(bake) 옵션을 추가합니다.

### 8.3 떠 있는 발판과 고저차가 필수인 이유

평면 복도만으로는 난이도 표를 만족할 수 없습니다. 산술은 이렇습니다:

- 점프 상승 시간 ≈ 320/900 = 0.356초, 공중 체류 ≈ 0.71초
- 130 px/s × 0.71초 = **약 92px** 가 평면에서 건널 수 있는 최대 틈
- 꼬리치기 반동(위로 150px/s) 한 번이 공중 체류를 늘려 **실측 142.3px** 추가 → 평면 106.5px 대비 약 36px
- **반동 2회는 도달거리를 늘리지 않는다**(실측 142.3px = 142.3px). 연쇄 반동 전제는 성립하지 않는다.
- 레벨 5의 `recoil_max_gap_px`는 **170px**

즉 평면에서 170px 틈은 물리적으로 건널 수 없습니다. 이를 만족하려면 **높은 곳에서 뛰어내리거나(약 150px 고저차)** 해결합니다. 다만 반동 연쇄가 불가하므로, 생성기는 틈 너비를 단일 반동 도달거리 이내로 clamp하고 난이도 표는 의도한 최대로 남깁니다(8.3). 따라서 떠 있는 발판과 고저차는 선택이 아니라 난이도 표를 성립시키기 위한 조건입니다.

고저차가 있으면 다음도 같이 성립합니다:

- 고드름이 매달 **천장**이 생깁니다 (발판 아래).
- 꼬리치기 반동이 닿을 **높은 발판**이 생겨 반동이 이동 수단이 됩니다.

카메라는 수평 추적 + 수직 데드존으로 고저차를 따라갑니다.

### 9.1 씬 전환

`game_state.gd` (Autoload) 가 현재 레벨 인덱스와 체력을 들고 있습니다. 레벨 클리어 → `level_complete.tscn` → 다음 레벨 로드 → `level.tscn` 재인스턴스. 사망은 씬 전환 없이 `level.tscn` 내부에서 상태만 리셋합니다 (5.5 이유).

## 13. 검증 방법

코드를 한 줄이라도 쓰기 전에, 다음 검증이 통과해야 합니다.

### 13.1 정적 검증

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --check-only \
  -s scripts/seal_baby.gd
```

모든 `.gd` 파일과 `.tscn` 파일에 대해 파싱 오류가 없어야 합니다.

### 13.2 headless 통합 검증

`tests/test_runner.tscn` 을 headless로 실행해 다음을 확인합니다:

1. `seal_baby.tscn` 인스턴스화 성공
2. 5개 씬 전부 인스턴스화 성공
3. 각 레벨 `LevelData` 로 `level_generator.gd` 실행 → 지형 세그먼트가 생성되고, **평면 틈이 전부 `flat_max_gap_px`(92) 이하**인지 검사
4. 아기 물범을 레벨에 배치하고 60프레임 시뮬레이션 → 지면에 닿아 있고, 화면 밖으로 나가지 않음
5. 꼬리치기 입력 발생 → `SwatHitbox`가 0.15초간 활성화되고 0.40초 후에야 다시 활성화 가능
6. 게와 충돌 → 하트 1 감소. 게에 꼬리치기 → 게 파괴
7. 레벨 끝 도달 → 레벨 클리어 상태 전환
8. **레벨 1의 `swat_wall_count` + `recoil_gap_count` 가 0인지**, **레벨 2~5는 각각 1 이상인지** 검사. 8번은 2장의 안티목표를 데이터로 보장하는 검사입니다.

하나라도 실패하면 비정상 종료 코드로 끝냅니다.

### 13.3 수동 검증

`godot --path .` 로 실행해 직접 플레이. 확인할 것:

- 레벨 1은 점프만으로 클리어 가능한가
- **레벨 2에서 꼬리치기를 전혀 쓰지 않고 클리어를 시도 → 실패하는가.** 이것이 이 게임의 핵심 전제입니다. 통과하면 설계가 아니라 버그입니다.
- 레벨 3의 반동 틈에서, 반동 대상(게/블록)을 치면 높은 발판에 닿는가
- 레벨 5의 밀려오는 빙산이 레벨을 클리어 불가능하게 만들지 않는가 (압박이지 벽이 아니어야)
- 레벨 5에서 죽고 부활한 뒤, 빙산이 플레이어를 덮치지 않는가 (5.7 재배치 규칙)
- 입력 씹힘이 없는가

### 13.4 그림 교체 검증

PNG가 도착한 뒤:

1. `tools/prepare_sprites.sh` 실행
2. `assets/sprites/`에 규격 파일 존재 확인
3. `PolygonPuppet`을 제거하고 `SpriteSwap`에 `AnimatedSprite2D` 장착
4. **스크립트와 애니메이션 파일을 한 줄도 수정하지 않았는지** 확인
5. headless 통합 검증 1~7 재실행 → 전부 통과

5번이 이 설계의 핵심 검증입니다. 여기서 스크립트를 고쳐야 한다면 7장의 구조가 잘못된 것입니다.

**태스크 14에서 이 검증을 자동화했다.** 실제 PNG가 도착하지 않아도 교체 *메커니즘*을
합성 스프라이트(`Image` API로 만든 단색 텍스처)로 증명한다: 모든 `VisualSlot`의
도형을 지우고 스프라이트를 붙인 뒤에도 이동·꼬리치기·애니메이션이 그대로이고,
`scripts/`의 어떤 스크립트도 시각 노드를 이름으로 참조하지 않는다. 애니메이션
트랙은 허용된 피벗 프로퍼티 여덟 개만 겨냥할 수 있다(금지 목록이 아니라 허용
목록으로 검사한다).

`tools/prepare_sprites.sh`가 `png-prompts.md` 11장의 후처리(마젠타 키 → 균일 축소
→ `assets/sprites/` 배치)를 자동화한다. `raw/`가 없거나 비어 있으면 경고만 하고
종료 코드는 0으로 둔다 — 그림은 아직 도착하지 않았을 수 있기 때문이다.
